# 测试与平台上报说明

本说明对应工作台 0.1.4 的实际实现，适用于 [Windows](windows.md) 和 [macOS](macos.md)。工作台默认运行随机探索，业务性质断言须按官方 Kea2 方式另外编写、运行；当前页面不提供脚本上传、APK 安装或自定义 Kea2 命令参数输入。

## 测试参数

| 页面字段 | 默认值 | 实际范围与含义 |
|---|---|---|
| 测试设备 | 选择在线设备 | 仅 `adb devices -l` 状态为 `device` 的设备可启动；一台自动选中，多台手选，无固定默认序列号 |
| App 包名 | `com.ugreen.iot` | 须已安装，符合点分包名格式；启用平台上报时须在项目映射中 |
| 测试时长（分钟） | 600 | 1–10080；600 分钟为 10 小时 |
| 最大步数 | 99999 | 1–2147483647；时长或步数任一达到限制即结束 |
| 操作间隔（毫秒） | 500 | 0–60000 |
| 数据采集周期（步） | 25 | 1–10000；传给上游 `--profile-period`，并非网页轮询或上报间隔 |
| 采集执行截图 | 开启 | 关闭时不传截图开关和前后截图参数 |
| 失败前截图（张） | 20 | 0–1000；0 表示每步采集 |
| 失败后截图（张） | 5 | 0–1000；截图开启时不得大于失败前数量，因此失败前为 0 时失败后也设 0 |
| 同步到测试平台 | 开启 | 不需要平台时主动关闭；开启时需有效项目关联及非空 MinIO 凭据 |

页面预览展示 `kea2 run ...` 的主要参数。实际执行使用同一虚拟环境的 Python，额外包含输出路径与 `--log-stamp`；Windows 通过工作台适配入口处理停止信号，再调用官方 CLI。真实命令保存在 `run.json` 的 `command` 字段。

工作台启动前检查设备在线、App 已安装、同一设备没有本工作台的活动任务，并通过 `ps -A` 检查 `com.android.commands.monkey` 进程。已有 Monkey / Fastbot 时会拒绝启动。请结束原任务并确认设备清理，避免直接杀死其他使用者的测试。

## 执行状态与停止

| 状态 | 含义 |
|---|---|
| 准备中 | 已建立记录，正在启动或准备设备；未收到正式探索计时 |
| 运行中 | 已收到 Kea2 探索日志；页面显示发送步数和探索时长 |
| 正在停止 | 已请求中断，等待 Kea2 清理 |
| 生成报告 | Kea2 已输出生成报告日志，仍属于活动状态 |
| 已完成 | 执行完成；质量结果另看 Crash / ANR 和原生报告 |
| 已取消 | 用户请求停止后完成收尾 |
| 异常终止 | 启动/执行异常、停止超时，或服务重启时发现上次未结束记录 |

工作台把上游退出码 0–3 当作可完成的执行，退出码 1–3 会使问题统计至少为 1。这一统计优先来自设备日志中的 Crash / ANR 标记，退出码兜底值不能代替原生报告里的缺陷详情。平台的执行完成状态与质量通过/失败分别表达。

点击“停止测试”后，macOS 发送 SIGINT；Windows 对新建子进程组发送 Ctrl+Break，由适配入口转为 `KeyboardInterrupt`，进入 Kea2 清理流程。停止超过 90 秒会强制结束，标记异常并提示设备清理未确认。强制结束不能保证手机端残留进程清理或原始材料完整。

刷新/关闭浏览器不停止测试。关闭原始启动终端会结束服务并释放端口；启动器异常退出时，控制管道 EOF 也会触发服务退出，收尾阻塞时最多等待约 5 秒后强制结束。正常按 Ctrl+C 时请求停止任务并等待收尾；建议先通过页面完成停止、报告与上报。服务意外退出不自动续跑，重启同一工作目录会把未完成记录标为异常终止。检查手机残留进程后新建测试；已达标且最终状态未同步的记录可尝试补报。

## 报告与数据

默认工作目录为启动命令的当前目录，使用 `--root` 可明确指定。`--root` 同时决定配置查找路径、设置保存和历史数据位置；源码包的根目录已有 `configs/`，新的 wheel 工作目录需先 `kea2 init`。

服务优先绑定 4320（或 `--port` / 双击入口 `KEA2_PORT` 指定的首选端口）；被占用时直接绑定系统分配的可用端口。双击入口在服务就绪后使用实际地址打开浏览器，并通过 `data/launcher.json` 记录该工作目录的地址以供重复启动时复用。手动命令也会自动选择端口，请以终端输出为准。

```text
<工作目录>/
├── configs/                         官方 Kea2 配置
├── data/settings.json               页面保存的连接设置
└── artifacts/<运行编号>/
    ├── run.json                     参数、实际命令、状态、连接快照、上报状态
    ├── console.log                  完整执行输出
    ├── index.html                   工作台报告
    ├── raw/res_<运行编号>/           上游原始结果、日志、截图、覆盖率等
    │   └── bug_report.html          原生报告（生成成功时）
    ├── report-generation.log        工作台补充生成报告的输出（如发生）
    ├── external-report-request.json 最后一次提交请求（如发生）
    └── external-report-response.json 最后一次成功且校验通过的回执（如发生）
```

运行目录还可能出现 `.platform-snapshot/`，用于报告上传快照，不作为网页公开路径。请求/回执文件为当前保存版本，不是每次上报的完整历史；失败时回执可能仍是此前成功版本，应结合请求中的版本和 `run.json` 的 `delivery` 判读。

工作台最近日志保留 160 行，HTML 报告中展示最近 80 行，完整内容在 `console.log`。正常结束时先保存最终本地报告，再尝试最终平台同步；即使上报失败也可查看本地材料。准备阶段失败时可能没有原生结果目录；停止超时可能只有部分数据。

截图 20/5 模式保留失败上下文，没有失败时不保证生成失败截图文件。工作台步数取自 Kea2 的发送日志，探索时长取自 `[New Iteration] Elapsed`；原生报告的 Executed Events 和 Total Testing Time 使用上游设备日志统计，可能略少，保留各自口径。页面“已完成”不等于质量无缺陷。

通过“查看测试报告”使用工作台 HTTP 地址打开报告；转移报告时复制整个运行目录。HTML 可以静态查看，但原生报告依赖的资源必须保留相对路径。运行页面每 2 秒查询状态（页面可见时），已打开的报告页需刷新才能看到新的静态内容。

本机 `data/settings.json` 和运行 `run.json` 的 `settings` 保存访问凭据。内部归档时保管这些文件，分享报告前应移除本地 `run.json` 的 `settings`；平台上传快照会自动去掉该字段。默认没有登录机制，保持本机监听即可避免把连接设置暴露为公共服务。

## 连接设置

点击右上角“设置”，填写并保存：

默认平台页面地址为 `http://aitest_engine.ugreencloud.com`，结果上报接口为 `http://aitest_engine.ugreencloud.com/api/tasks/external-reports`。报告文件仍通过 MinIO 上传并从配置的公开地址访问；平台页面地址与存储服务地址分别配置。

| 字段 | 作用与要求 |
|---|---|
| 结果上报接口 | 完整 HTTP/HTTPS URL；当前协议为 `POST /api/tasks/external-reports` |
| 平台页面地址 | 用于“平台记录”跳转；拼接 `/task-center?taskId=...` |
| 服务 ID / 能力 ID | 使用平台已登记的 Kea2 专用身份，两者须匹配部署；不复用其他专项身份 |
| 存储服务地址 | MinIO 的 HTTP/HTTPS 地址，例如 `https://minio.example.com:9000`，应为服务端点，不含桶路径 |
| 存储桶 | 已创建且凭据可写入的桶；程序不会自动建桶 |
| 报告目录前缀 | 桶内目录，默认 `kea2`；报告对象路径为 `<前缀>/runs/<运行编号>/...` |
| Access Key / Secret Key | MinIO 写入凭据；未配置或留空时使用本工具内置默认值，显式填写的非空值优先 |
| 公开访问根地址（选填） | 报告访问 URL 中前缀之前的根地址，须对应存储桶的根；留空使用 `<存储服务地址>/<桶>` |

例如公开根地址为 `https://reports.example.com/autotest-reports`、前缀为 `kea2`，得到 `https://reports.example.com/autotest-reports/kea2/runs/<运行编号>/index.html`。本机 `127.0.0.1` 地址无法替代平台读者可访问的报告地址；当前实现不生成预签名 URL，也不自动配置 MinIO 读权限。

默认连接来源按顺序为 `data/settings.json`、工作目录中的 `settings.example.json`、安装包内置示例。示例给出当前内部平台地址、服务/能力 ID 及默认 MinIO 凭据；其他环境可按部署自定义。读取旧配置或保存设置时，Access Key / Secret Key 缺失、为 null、空字符串或纯空白均按字段回退到内置默认值，显式配置的非空值保留。清空这两个输入框并保存即可恢复默认值，设置窗口会显示最终生效的配置。页面保存验证必填字段和地址基本格式，不测试网络、桶权限或凭据有效性；这些问题在实际上传中暴露。当前上报请求没有额外的认证 Header 配置项。

升级已有环境时，已保存的连接设置仍优先。请在“设置”中核对并保存上述平台页面地址及结果上报接口，新建任务才会使用新目标。正式平台任务中心需要登录，结果上报接口沿用已登记的服务与能力身份。

每个任务保留创建时的完整连接快照。修改“设置”只影响新任务，旧任务补报仍使用旧值；修复服务器网络/权限后可重试旧任务，若需更换凭据或上报目标，应按新设置新建测试。

## 平台上报

### 项目关联和达标条件

| App 包名 | 自动关联项目 |
|---|---|
| `com.ugreen.iot` | `69684909ee73c95fe1643567`（APP-绿联声学） |
| `com.ugreen.iot.connect` | `696eded40e4637c8b71e22a1`（APP-绿联智联） |

未关联 App 可关闭平台上报后执行。页面不提供手动项目 ID；新增映射需要修改 `kea_workbench/models.py` 并重新打包安装。其他平台环境的项目 ID 也需核对映射。

上报资格同时满足：

1. 本次启用平台上报。
2. 配置时长至少 5 分钟。
3. 正式探索日志中的实际时长达到 300 秒，准备与报告收尾不计入。
4. 资格取得前没有检测到 Crash / ANR；若此前发现问题，记录 `gateBlocked`，本次不能取得资格。

配置恰好 5 分钟并不保证达标，步数提前耗尽或计时日志未达到 300 秒都会跳过；需要上报时可预留更长时长，并核对实际进度。取得资格后记录 `qualifiedAt`，后续异常或主动取消仍提交最终数据。

### 上传、提交与回执

资格取得触发后台同步。每轮按记录快照生成过程报告、复制原始依赖、上传变更文件，最后更新同一 `index.html`；没有变更的依赖文件可跳过上传。循环等待约 15 秒，报告生成、文件量、网络耗时会延长间隔，不保证严格每 15 秒提交一次。测试与网络同步分线程执行。

上传成功后向接口提交 `projectId/serviceId/capabilityId/externalFields`，沿用运行编号作为 `externalTaskId`，同一运行更新同一平台任务与报告地址。`custom.sync` 带递增 `revision`、达标标记、执行阶段及最终标记。平台回执必须确认任务 ID、项目、服务/能力、外部运行编号、任务名、状态、统计和同步版本，否则显示上报失败。请求最多尝试 3 次；一般 4xx（除 408/429）不重试同一请求。

| 本地状态 | 平台执行状态 | 质量统计 |
|---|---|---|
| 活动状态 | `running` | 暂未给出最终 passed/failed |
| 已完成 | `succeeded` | 无问题才计 passed；发现问题计 failed |
| 已取消 | `canceled` | 最终统计计 failed |
| 异常终止 | `failed` | 最终统计计 failed |

`resultSummary.total` 固定为 1，表示这一运行的汇总结论，并非执行步数；步数及 Crash / ANR 分别存放在 `steps` 和 `crashesAndAnrs`。

### 查看和补报

| 页面上报状态 | 含义与操作 |
|---|---|
| 待达标 | 上报开启，但尚无资格 |
| 同步中 | 已达标或正在提交 |
| 已上报 | 最近一次快照收到有效回执；任务仍活动时不表示最终上报已完成 |
| 上报失败 | 查看页面错误与运行目录请求、回执，排查网络、配置、桶权限、平台契约 |
| 未达门槛 | 结束时未取得资格，保留本地报告，不允许补报 |
| 已关闭 | 本次未启用上报 |

有效回执带回 `taskId` 后显示“平台记录”，跳到配置的任务中心。在线报告 URL 保存在 `delivery.reportUrl`；平台需支持本工具外部上报协议才能展示与持续更新。对接环境可在“生命周期运行记录”或“质量工作台”的“外部服务上报”记录中进入“查看详情 → 报告与制品”；菜单、刷新策略由平台部署实现，工作台本身不控制平台列表。

心跳约定 `heartbeatSeconds=180` 随每个请求提交。平台如何处理超过 3 分钟未更新的记录由平台实现；本机服务不会自动接续被中断任务。

测试结束后提交最终快照。网络失败不改变本地执行结论；失败的终态记录显示“重试上报”。需等待当前执行和上报线程退出，点击重试仅用本地材料，不连接设备。未达标、上报关闭或仍在执行/同步的任务不能补报。故障排查时不要用最近一次“已上报”替代最终状态确认。
